No deployment performed. Before any production deployment: complete authentication, server APIs, tested migrations/RLS, private storage, durable queue/Node worker, sandbox Stripe, provider contracts, threat/retention/legal reviews and monitoring. Request user authorization before publication/live charging.
Database development requires Docker and Supabase CLI: supabase start; supabase db reset; supabase test db. Run only against local development, never production. No Supabase CLI/Docker available during initial build. Database CI must be added with Supabase local setup before release.
Secrets listed in .env.example are server-only placeholders. Filling them does not activate unimplemented integrations. No production runtime available to configure.
Rollback: preserve immutable audit evidence and financial ledger, take backups before reviewed migrations, roll back frontend version independently; use tested forward corrective database migrations. Recovery is a design requirement, not exercised here.

## NEN analysis pilot

The Worker serves the frontend and `/api/nen/analysis`. A GET reports whether the required bindings and source configuration are present. A POST starts the analysis and streams NDJSON progress, errors and the result while the browser stays connected. Workers AI and the rate-limit binding are configured in Wrangler. The deployed route returns 503 until a source endpoint is configured.

Use an authorized machine-data source that can look up the exact NEN reference and return the public attachment URLs, including clarifications and amendments. NIPEZ identifies its profile XML and ISVZ open data as machine interfaces. A frontend endpoint or a list of notices alone cannot supply this contract. Verify the completeness and download terms of the chosen source before enabling it. [NIPEZ rules](https://podpora.nipez.cz/cs/pravidla-pouziti-sluzeb-nipez/latest/pravidla-pro-pouzivani-api-systemu-nipez)

Set `NEN_SOURCE_URL` on the Worker to the HTTPS resolver endpoint. It receives a GET with the normalized `reference` query parameter. If authentication is required, add the server-side secret `NEN_SOURCE_TOKEN`; it is sent as a Bearer token to the resolver only. Configure `NEN_DOCUMENT_ORIGINS` as a comma-separated list of approved HTTPS origins if downloads use hosts other than NEN or Zakázky GOV. The Worker validates every redirect against that list.

The resolver returns JSON with `reference`, `title`, optional `authority`, `complete` and `documents`. Each document includes `name` and `downloadUrl`, with optional `kind` (`documentation`, `clarification`, `amendment` or `other`) and offset-aware ISO `publishedAt`. Use `complete: true` only when the resolver confirms the public document inventory. Return 404 for a missing tender.

The pilot accepts text-layer PDF, DOCX, XLSX, TXT, CSV, XML and ZIP. It records encrypted, oversized, unreadable and unsupported files in the result. Limits include 15 top-level downloads, 8 MiB per downloaded file, 24 MiB of successful downloads and 140,000 extracted characters. Scanned pages, segmented ZIP, and RAR require separate support. The app exposes file-level gaps and retains only findings with exact citations from extracted text. The request does not persist source files or results on the server.
